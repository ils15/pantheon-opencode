## 🟥 CRÍTICOS (5)

### C1. Plugin de hooks NUNCA é registrado → sistema de hooks é código morto
- **Onde:** `opencode.json:3` (`"plugin": []`), `tui.json:3-5` (só `plugins/pantheon-tui`), pasta `plugins/` (plural)
- **Problema:** o auto-load do opencode procura em `plugin/` (singular) e/ou no array `plugin` do config. O `pantheon-hooks.ts` nunca é carregado.
- **Impacto:** todos os hooks de segurança (validate-talos-scope, scan-secrets, validate-post-conditions) e logs de delegação NUNCA rodam.
- **Fix:** `"plugin": ["plugins/pantheon-hooks.ts"]` no `opencode.json` (ou mover para `plugin/`).

### C2. Hooks de validação NUNCA recebem payload → no-op silencioso (mesmo se registrados)
- **Onde:** `plugins/pantheon-hooks.ts:151-152, 77-80` — `runHook(h.script, h.timeout)` sem `options.input`
- **Problema:** a API `tool.execute.before` do SDK 1.18.13 (`@opencode-ai/plugin/dist/index.d.ts:235-241`) só entrega `{tool, sessionID, callID}` — NÃO há args. Os hooks leem stdin vazio.
- **Impacto:** `scan-secrets.sh` nunca vê payload → exit 0 (gate de secrets inerte); `validate-talos-scope.sh` → AGENT_NAME="" → sempre skip; `format-multi-language.sh` nunca formata. Os logs provam: `"agent":"unknown","task":""`.
- **Fix:** mapear `{tool_name, tool_input, agent_id}` para JSON e gravar no stdin dos hooks `before`; usar `input.args` de `tool.execute.after` quando precisar de args.

### C3. `NameError: name 'uuid' is not defined` — mcp_persistence_server.py:599
- **Onde:** `scripts/mcp_persistence_server.py:599` — `actual_session = session_id or uuid.uuid4().hex[:12]`
- **Problema:** não há `import uuid` no arquivo (verificado: imports são argparse, re, sqlite3, sys, datetime, Path, _pantheon_paths, FastMCP).
- **Impacto:** `context_save` CRASHA sempre que session_id é omitido (o caso documentado "auto-generated if None"). Todo o sistema de checkpoints de contexto fica inoperante.
- **Fix:** adicionar `import uuid`.

### C4. `$` chain quebrada — `.timeout()` não existe na API (issue #14)
- **Onde:** `plugins/pantheon-hooks.ts` (versão .bak) — `$\`bash ...\`.quiet().nothrow().timeout(timeoutMs)`
- **Problema:** `BunShell`/`BunShellPromise` em `shell.d.ts` (1.15.12 E 1.18.12) só têm `quiet()`, `nothrow()`, `throws()`, `cwd()`, `env()`. `.timeout()` NÃO existe → `TypeError` em todo tool execute (113k× no log).
- **Fix:** reescrever `runHook` com `node:child_process.execFile` (timeout nativo + SIGKILL + maxBuffer 10MB). Já validado localmente.

### C5. Hook de segurança trava 30s — child herda stdin do TUI, `cat` nunca vê EOF
- **Onde:** `scripts/hooks/validate-talos-scope.sh:7` (`INPUT=$(cat)`) + plugin sem `stdio: ["ignore", ...]`
- **Problema:** o child herda o stdin do processo opencode (TUI) → `cat` bloqueia para sempre → timeout 30s → SIGKILL. Confirmado no log pós-restart: `WARN "Hook validate-talos-scope.sh timed out after 30000ms"` (4×).
- **Impacto:** cada execução de bash/edit atrasa 30s.
- **Fix:** no plugin, `stdio: ["ignore", "pipe", "pipe"]` no execFile (cat recebe EOF imediato) — cuidado com exclusão mútua `input` × `stdio:["ignore"]`.

## 🟠 ALTOS (7)

### A1. Path traversal contornável — prefix check em vez de containment
- **Onde:** `scripts/mcp_resources_server.py:191-195` — `if not str(resolved).startswith(str(mb_dir))`
- **Problema:** `path = "../memory-bankX/arquivo"` (dir irmão cujo path começa com a string de mb_dir) passa na checagem → lê arquivos fora de memory-bank/.
- **Fix:** `resolved.is_relative_to(mb_dir)` (Python ≥3.9). Mesma correção em `code_mode_server.py:81` (menos crítico lá).

### A2. Build do TUI quebrado — 4 cópias divergentes, dist/ stale
- **Onde:** `plugins/pantheon-tui/` — `index.tsx` raiz 1189 linhas (v1.2.0 atual), `src/index.tsx` 144 linhas (v1.0.x), `dist/tui.tsx` 254 linhas (v1.1.x), `dist/tui.js` 143 linhas (v1.0.x compilado)
- **Problema:** `package.json:15` `"build": "tsdown && cp src/index.tsx dist/tui.tsx"` — builda a versão VELHA; o `index.tsx` raiz nunca é buildado. `exports["./tui"]` aponta para dist stale (254 linhas, sem usage-bar, `file.read({query:{...}})` assinatura antiga, fallback `'1.0.1'`).
- **Fix:** mover código do `index.tsx` raiz → `src/index.tsx` e rebuildar, OU trocar exports para `"./tui": "./index.tsx"`.

### A3. `checkpoint-session.sh` referenciado mas INEXISTENTE
- **Onde:** `routing.yml:429` + `instructions/checkpoint-standards.instructions.md:171` → `.pantheon/code-mode/` só tem `.gitkeep` e `example-sync.sh`
- **Impacto:** `auto_continue.checkpoint_script` aponta para arquivo ausente → checkpoint do auto-continue quebra silenciosamente.
- **Fix:** criar `checkpoint-session.sh` ou remover a referência.

### A4. `kv_search` quebra para termos com pontuação
- **Onde:** `scripts/mcp_persistence_server.py:415-419` — `terms = [re.escape(t) for t in terms]`
- **Problema:** `re.escape` insere backslashes que o FTS5 trata como literais → `"set\-tier"` nunca casa `"set-tier"` → busca vazia. Inconsistente com `memory_mcp_server.py:348` (não escapa nada).
- **Fix:** escapar só aspas (`t.replace('"', '""')`) para FTS5.

### A5. `memory_forget` por key deixa embeddings órfãos
- **Onde:** `scripts/memory_mcp_server.py:464-468, 71-74` — deletar por key não toca `vec_memories`; docstring (L438-440 "removed automatically via CASCADE / triggers") é FALSA (só há triggers FTS, L83-100).
- **Impacto:** acúmulo de rows órfãos em `vec_memories`; `memory_stats.vector_entries` diverge.
- **Fix:** resolver id antes de deletar e remover de `vec_memories` (como já feito no caminho por id, L476), ou trigger.

### A6. `validate-talos-scope.sh` — lógica morta + custo alto + python3 do sistema
- **Onde:** `scripts/hooks/validate-talos-scope.sh` — L10-14: 6+ invocações `python3 -c` por chamada; L28-40: `FILE_COUNT` computado e nunca usado (dead code); L22: checa `command` como se fosse caminho de arquivo.
- **Impacto:** guard de escopo do Talos não bloqueia nada; acoplamento a python3 do PATH do sistema.
- **Fix:** receber payload via stdin do plugin e parsear com um único python3/jq; remover FILE_COUNT.

### A7. venv 5.4GB inflado — torch + nvidia-cuda não utilizados
- **Onde:** `.venv/` — `torch 2.13` + `nvidia-cuda-*` puxados por `sentence-transformers`; NENHUM script importa (só fastembed/onnxruntime). `requirements-vision.txt` incompleto (falta fastembed, sqlite-vec, pyyaml) e sem lockfile Python.
- **Impacto:** ~5GB de peso morto; venv não reproduzível.
- **Fix:** `pip uninstall torch sentence-transformers transformers chromadb`; `pip freeze > requirements.lock`; criar `requirements.txt` completo.
